## Known differences from MAME

- **Raster IRQ** (Guardians' rowscroll scenes): MAME redraws the screen up to the IRQ's line at each raster IRQ
  (`update_partial`); the core draws each line one line ahead of the beam.  The core raises the IRQ for line N where MAME's beam
  is at line N (one line before line N is shown) and, while 0x3c bit 0 is set, starts drawing a line `rdly` (144) dots after
  that, so the handler's writes reach the lines MAME gives them: the replay model above shows that this gives MAME's pictures.
- **Frame timing**: MAME runs every set at 60 Hz on a 0x200 x 0x100 raster with a 2500 us vblank; the core uses the CRTC values the
  games program and the boards' dot clocks (PLAN.md), but 262 lines for Guardians (409 x 262, 58.3 Hz; CRTC 411 x 259) and
  Penguin Brothers / A-Blast (445 x 262, 60.0 Hz; CRTC 449 x 256): the RetroTINK 4K's "MiSTer 240p" class (README, Timing).
  The others ~60-60.5 Hz.
- **Palette**: MAME turns pens into colours when the frame is read out (the palette at the end of the frame); the core looks the
  palette up as the dots go out.  A palette written during a frame shows from the line after the write.
- **CPU**: program reads that miss the 8 KB cache wait for the DDR3 (MAME: no wait states).
- **X1-010 write timing**: MAME 0.289's `x1_010_device::write` does not bring the stream up to date before it changes a register, so in
  MAME a key-on / key-off or a pitch change takes effect from the start of the sound update the write falls in (6-20 ms early in the Guardians recording);
  the core applies each write when the CPU makes it.
- **Gundam EX**: the EEPROM starts from the MRA's image at every load (MAME keeps its nvram).
- **Sync widths**: by default (OSD "Sync widths: Standard") the horizontal sync is at most ~4.7 us and the vertical sync at most 3
  lines; the games program longer ones (Guardians 7.5 us / 4 lines, Penguin Brothers 9.1 us / 4 lines), which the owner's CRT showed
  dark and unsteady.  "Board" gives the programmed widths.
- **No image loaded** (e.g. a zip missing, so Main_MiSTer sends none): the core shows its boards' timing with a black picture, so the
  OSD and Main's message are visible (with the all-zero header the sync was unusable: the MiSTer looked hung).
