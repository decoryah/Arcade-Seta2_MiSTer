MAME 0.289 is the reference (`src/mame/seta/seta2.cpp`, `src/devices/video/x1_020_dx_101.cpp`,
`src/devices/cpu/m68000/tmp68301.cpp`, `src/devices/sound/x1_010.cpp`, `src/devices/machine/eepromser.cpp`).

Phase 2, the light-gun games (MAME's `samshoot`): deerhunt, deerhunta-e, deerhuntj, turkhunt, wschamp, wschampa, wschampb, trophyh,
trophyht.

## Known differences from MAME

- **Raster IRQ** (Guardians' rowscroll scenes): MAME redraws the screen up to the IRQ's line at each raster IRQ
  (`update_partial`); the core draws each line one line ahead of the beam.  The core raises the IRQ for line N where MAME's beam
  is at line N (one line before line N is shown) and, while 0x3c bit 0 is set, starts drawing a line `rdly` (144) dots after
  that, so the handler's writes reach the lines MAME gives them: the replay model above shows that this gives MAME's pictures.
- **Frame timing**: MAME runs every set at 60 Hz on a 0x200 x 0x100 raster with a 2500 us vblank; the core uses the CRTC values the
  games program and the boards' dot clocks (PLAN.md), but 262 lines for Guardians (409 x 262, 58.3 Hz; CRTC 411 x 259) and
  Penguin Brothers / A-Blast (445 x 262, 60.0 Hz; CRTC 449 x 256): the RetroTINK 4K's "MiSTer 240p" class (README, Timing).
  The others ~60-60.5 Hz.
- **Palette**: MAME turns pens into colours when the frame is read out (the palette at the end of the frame); the core looks the
  palette up as the dots go out.  A palette written during a frame shows from the line after the write.
- **CPU**: program reads that miss the 8 KB cache wait for the DDR3 (MAME: no wait states).
- **X1-010 write timing**: MAME 0.289's `x1_010_device::write` does not bring the stream up to date before it changes a register, so in
  MAME a key-on / key-off or a pitch change takes effect from the start of the sound update the write falls in (6-20 ms early in the Guardians recording);
  the core applies each write when the CPU makes it.
- **Gundam EX**: the EEPROM starts from the MRA's image at every load (MAME keeps its nvram).
- **X1-010 key-on flags**: MAME 0.289's `x1_010_device::read` returns a channel's flag without updating the stream, so a flag
  clears there only at the next sound update; the core clears it when the sample ends. A game that polls the flags (the light-gun
  games' sound drivers do) can take another path than in MAME: the likely reason Deer Hunting draws another wind in the scripted
  play, Wing Shooting's attract birds fly another path and its map's dog picks another hunting spot.
- **The light-gun games' DSW2**: MAME 0.289 connects DSW2 to the TMP68301 parallel port's write side
  (`parallel_w_cb().set_ioport("DSW2")`), so in MAME the games read 0xFFFF there whatever the DIP menu says (flip screen, demo
  sounds, difficulty, blood colour, lives and gun type stay at their "off" settings). The core gives the port the switches, as the
  board's wiring would, so the DIP menu works; the benches compare with DSW2 = 0xFF. Trophy Hunting's location test therefore runs
  with its default "Gun Type (Leave on Hand Gun)" = Hand Gun in the core and Pump Action in MAME.
- **The light-gun games' battery RAM**: MAME has 64 KB at 0x300000 and saves it whole. After power-on the games write only its first
  2 KB (MAME, 100 s of scripted play each, `NVUSE=1`: Deer Hunting and Trophy Hunting 0x300000-0x3007FF, Turkey Hunting and Wing
  Shooting 0x300000-0x3003FF; at power-on Turkey Hunting and Wing Shooting also write up to 0x300FFF, Trophy Hunting all 64 KB, its
  RAM check), so the core keeps 0x300000-0x301FFF in block RAM and saves that (8 KB, the same bytes as the start of MAME's file);
  0x302000-0x30FFFF is in the DDR3 and not saved. Trophy Hunting's check restores what it finds: started in MAME from a saved file
  with random bytes above 8 KB (what the DDR3 may hold), its first 900 frames (88 pictures) and the first 8 KB it saves are the same
  as with the whole file.
- **Sync widths**: by default (OSD "Sync widths: Standard") the horizontal sync is at most ~4.7 us and the vertical sync at most 3
  lines; the games program longer ones (Guardians 7.5 us / 4 lines, Penguin Brothers 9.1 us / 4 lines), which the owner's CRT showed
  dark and unsteady.  "Board" gives the programmed widths.
- **No image loaded** (e.g. a zip missing, so Main_MiSTer sends none): the core shows its boards' timing with a black picture, so the
  OSD and Main's message are visible (with the all-zero header the sync was unusable: the MiSTer looked hung).
